# Customer administration release — 16 November 2026

The super administrator signs in on the ordinary website and is directed to Customer access. They can create named customers and administrators, add or rename administrators, set an access-through date, and switch each customer's access on or off. An empty expiry date on an existing customer means no expiry. A password-change form checks the current password. New administrator passwords require at least 12 characters. Passwords are hashed and cannot be displayed after creation.

Existing users, weighments, custom fields and settings were migrated to the existing customer. New customers have separate report fields, settings and weighments. Record and field route binding, report downloads, searches and API queries are scoped to the current customer. New customers' reports use their own customer name; the existing customer retains the Donito report branding. A disabled or expired customer is rejected on website requests and API requests; disabling also invalidates current API tokens. Access remains valid through the end of the chosen date in the server's configured timezone.

Desktop v1.5.0 polls for access and returns to sign-in after access is revoked. It requires online access validation when starting or refreshing and does not display unassigned legacy local-only records after a successful sync. A user's already downloaded files or offline copies cannot be remotely erased. Older desktop versions do not have the new polling behavior and should be upgraded.

Validation: 38 local Laravel tests with 264 assertions passed before the final small name-edit addition; the final customer-isolation suite passed 5 tests and 53 assertions including cross-tenant access, settings, expiry, disablement, password change and administrator rename. Desktop API and UI suites passed 15 tests. The migration passed on a populated MariaDB test database and on a restored copy of the live database. A database export and affected live files were backed up before deployment. Live tests verified the owner's login, current customer's records and report PDF, new customer creation, cross-customer web and API denial, disablement of active sessions and tokens, expired login rejection, and administrator rename. The temporary live QA customers were removed and pre-existing counts preserved. The packaged v1.5.0 app downloaded a password-protected report from the live server. The published installer SHA-256 matched the local build.

During live tests Hostinger intermittently returned a database connection error; a retry succeeded. This release does not commission the physical scale or cameras or guarantee one-second synchronization.
